# Threads Bot Blocker

偵測你 Threads 貼文底下的機器人／垃圾回覆，自動隱藏或送進待審清單，在本機網頁後台一鍵處理。
偵測方法可以用「規則包」分享，不必分享帳號名單。

## 它能做什麼，不能做什麼

Threads 官方 API **沒有「封鎖」與「檢舉」功能**，只允許對**你自己貼文**底下的回覆做「隱藏 / 取消隱藏」。所以：

| 能做 | 不能做 |
| --- | --- |
| 掃描你貼文的回覆並計算機器人分數 | 自動封鎖帳號 |
| 自動隱藏高分回覆（可復原） | 自動檢舉帳號 |
| 待審佇列、黑白名單、操作紀錄 | 掃描別人的貼文或全站 |
| 整理封鎖清單，一鍵開啟個人頁讓你手動封鎖 | |

我們刻意不做模擬點擊的自動封鎖／檢舉：那違反平台條款，會讓你的帳號有被限制的風險。

## 快速開始

需要 [Node.js](https://nodejs.org) 18 以上。**不需要安裝任何套件。**

1. 下載或 clone 這個專案
2. 取得 Threads 權杖（見下方）
3. 啟動
   - **Windows**：雙擊 [`start.bat`](start.bat)（第一次會幫你建立 `.env` 並用記事本打開）
   - **其他系統**：`cp .env.example .env`，填入權杖，然後 `npm start`
4. 開啟 http://localhost:3000 ，上方的**設定精靈**會告訴你權杖是否有效、權限是否足夠

### 取得 Threads 權杖

1. 到 [Meta 開發者後台](https://developers.facebook.com/apps) → **建立應用程式**，使用案例選 **存取 Threads API**。
2. 在使用案例中加入權限：`threads_basic`、`threads_read_replies`、`threads_manage_replies`。
3. **應用程式角色 → 新增用戶 → Threads 測試人員**，輸入你的 Threads 帳號；再到 Threads 的 **設定 → 帳號 → 網站權限 → 邀請** 接受。
4. 在使用者權杖產生器產生權杖，貼到 `.env` 的 `THREADS_ACCESS_TOKEN=`。

> 權杖只放 `.env`。不要貼到聊天、Issue 或截圖；外洩了就到後台重新產生。

## 功能

- **多種判斷合併計分（0–100）**：黑白名單、內建規則（連結、關鍵字、重複內容、短時間連發、帳號特徵）、**規則包**、AI（選用）
- **試跑模式**（預設）：只標記不動作，確認準確後再開啟自動隱藏
- **待審佇列**：列出判斷理由，可批次隱藏、保留（並加入白名單）、加入黑名單
- **封鎖清單**：黑名單帳號附個人頁連結，你在 Threads 按「⋯ → 封鎖」後回來標記
- **操作紀錄**與**取消隱藏**

## 規則包

規則包是純 JSON 的偵測規則，可以在社群之間分享。後台「規則包」分頁可貼上 JSON 或輸入 https 網址匯入，隨時停用或移除。

- 內建範例：[rules/tw-election-fake-accounts.json](rules/tw-election-fake-accounts.json)
- 格式與投稿守則：[rules/README.md](rules/README.md)
- 規則包**不含程式碼、不含正規表示式**，匯入前仍請先看過內容與來源
- 規則只會提高分數，不會繞過你的門檻與審核

## 選用：AI 判斷

在 `.env` 填入 `ANTHROPIC_API_KEY`，分數介於 20 與自動隱藏門檻之間的回覆會交給 AI 複判。回覆內容會被送到 Anthropic API；不想送出就不要填。

## 安全與隱私

- 伺服器只綁定 `127.0.0.1`，並檢查 Host／Origin
- 回覆內容一律以純文字顯示
- 資料（掃描結果、名單）只存在本機的 `data/`，不會上傳
- 詳見 [SECURITY.md](SECURITY.md)

## 負責任地使用

判斷是機率，不是事實。**先用試跑模式觀察，再決定是否自動隱藏**；對沒有證據的帳號，不要用「機器人」理由大量檢舉。
